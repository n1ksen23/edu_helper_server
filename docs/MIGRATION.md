# Анализ и решения миграции

Исходник: https://github.com/csgovideo1112-ux/homework, изучены app.js, index.html, style.css, config.js, data.json, schedule.json, notify.py и .github/workflows/notify.yml.

Проблемы: GitHub-токен в localStorage; полномочия через клиентский Telegram ID; общий JSON без транзакций и защиты от потери параллельных изменений; вычисление архива и дат на клиенте; жёсткая группа 4992; конечный массив времени пар; только пятидневный шаблон; нет датированных замен и подгрупп. Telegram SDK и цветовые переменные связывали UI с окружением Telegram. Уведомитель читает JSON одной группы и отправляет одному чату, не подходит для многогрупповой архитектуры.

Сохраняем карточку дня, три основных раздела, срочные ДЗ, сортировку и группировку. Авторизация теперь серверная, Argon2id, JWT на 10 минут с проверкой отзывной сессии на каждом запросе, ротация refresh-токена. Нативное хранение refresh через flutter_secure_storage, пароль не сохраняется. Web хранит сессию только в памяти; cookies не используются, поэтому cookie-CSRF отсутствует.

Приоритет явных правил при противоречиях ТЗ: ученик не выбирает подгруппу; все параллельные занятия видны. У ДЗ нет отдельного фильтра подгрупп: староста описывает разделение текстом. Время UI всегда московское; архив вычисляется SQL относительно часового пояса группы.

Шаблоны дней не действуют бессрочно: явное повторение создаёт записи дат. Датированное расписание хранит обе недели, календарь выбирает подходящие строки. Сырой защищённый API редактора сохраняет обе недели при редактировании. Воскресенье всегда пустое; ДЗ на воскресенье разрешено. Начальные данные: 7 ДЗ, исходные шаблоны и первые 18 недель от опорного понедельника. Импорт повторяемый и не перезаписывает правки.

План реализации: модели/миграция → авторизация → сервисы дат и архива → API → Flutter и формы → HTML-панель → импорт → тесты → release APK/AAB → VPS/HTTPS. Данные JSON в legacy/ являются только неизменяемым источником импорта.
